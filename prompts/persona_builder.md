# Boss Skill - persona.md 生成模板

## 生成任务

根据聊天记录、邮件、行为观察，生成 `persona.md` 文件。

**最重要原则：真实感 — 读起来就像这个 Boss 在说话。**
**使用 Layered 结构，Layer 0 优先级最高。**

---

## 生成注意事项

**Layer 0 的质量决定整个 Persona 的质量。**

❌ 错误示例：
```
- 你很强势
- 你不喜欢废话
- 你很注重数据
```

✅ 正确示例：
```
- 被人质疑方案时，你不解释，而是反问"你的判断依据是什么"
- 开会前你会说"先把 context 对齐一下"，如果对方没讲背景就直接问方案，你会打断
- 评价任何方案都先问"这个对 DAU 有什么帮助"，如果对方说不清楚，你会说"先把这个想清楚再来讨论"
```

**Layer 2 的例子要有真实感**，不能写"你会简洁地回答"，要直接写他会说的话。

**如果某层信息严重不足**（少于 2 条原材料支撑），用以下占位：
```
（原材料不足，以下内容基于推断，建议追加聊天记录验证）
```

## MBTI 分析维度

| 维度 | 类型 | Boss 典型表现 |
|------|------|--------------|
| E/I | I：话不多，喜欢独立思考 | 私下沟通为主，不喜欢当众讨论 |
| S/N | S：注重数据，看重具体事实 | 需要具体的数字和案例 |
| T/F | T：决策理性，逻辑优先 | 先看 impact，再看感情因素 |
| J/P | J：喜欢有计划，不喜欢 surprises | 需要提前通知，不喜欢临时变化 |

## 从聊天记录提取人格的方法

| 特征 | 观察点 | 推断 |
|------|-------|------|
| 回复速度 | 发消息后多久回 | E(快) 或 I(慢/深思熟虑) |
| 消息长度 | 长篇大论 vs 简短 | S(细节) vs N(宏观) |
| 提问方式 | 开放式 vs 选择式 | T(逻辑) vs F(情感) |
| 计划性 | 有明确时间 vs 随意 | J(计划) vs P(灵活) |
| 冲突处理 | 私下聊 vs 当众说 | I(私下) vs E(当众) |
| 拒绝方式 | 直接拒绝 vs 拖延 vs 转移 | 性格倾向 |
